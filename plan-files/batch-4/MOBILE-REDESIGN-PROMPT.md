## 0. Why
The owner reviewed the site on a phone: carousels scroll sideways, text is small (13 to 14px), the mobile menu is one long list. The owner approved the mobile designs in section 3 (samples were shown as screenshots; the pick letters are noted so the owner can match them). The owner's biggest fear is losing SEO.

## 1. SEO GUARDRAILS (hard rules, fail the work if broken)
1. **Nothing is removed.** Every word, heading, link, image alt, FAQ and schema block that is in the HTML today stays in the HTML. Collapsed or hidden-on-tap content is allowed only if it is in the DOM (`<details>`, or radio/checkbox + CSS). Never remove content on mobile, never load it with JavaScript later, never put it behind `display:none` generated by JS.
2. Same H1 to H6 text and order, same URLs, canonical, meta, schema (JSON-LD), internal links, `lang` attributes.
3. Mobile and desktop HTML stay the same. A mobile-only layout is done with CSS on the same markup. If a design needs a second copy of text (for example a duplicate for an auto-scroll loop), the copy gets `aria-hidden="true"` and `tabindex="-1"` on links, and the build parity tool must ignore it.
4. Tables stay real `<table>` elements. On phones CSS draws them in the new layout (section 3, Z3).
5. Text that carries the page's main keyword (H1, first paragraph, owner-keyword headings) is never collapsed. Only secondary text may be collapsed.
6. Run the existing parity tool before and after (target: same pass count as before, 0 missing words). Add a check that compares, per page, the list of headings, the list of internal links and the JSON-LD between the old `dist` and the new `dist` and fails on any difference.

## 2. Global mobile rules (max-width 759px unless noted)
- **No sideways swipe anywhere** except: (a) the auto-moving strips in section 3 (they move by themselves; people may also drag them), (b) code blocks (`pre`) inside articles. Remove `overflow-x:auto`, `scroll-snap-*` and `flex:0 0 <percent>` from every other element on phones. Known places: `.hp-swipe` (home.css ~line 353, used by bento, service cards, service links, reviews, guides), `.rp-stories`, `.rp-cmp-nav`, `.pp-tscroll`, `.tbl-wrap`, `main .card table`.
- **Font floor on phones:** body 16px minimum (the site body is 17px, keep it), secondary text 15px minimum, uppercase eyebrow labels 13px minimum with letter-spacing. Nothing under 13px. Fix every `font-size` below `.9375rem` that is body or secondary text (examples: `.hp-bento .hp-bc > p`, `.hp-list`, `.hp-svc-link .d`, `.hp-trust-t`, `.hp-stat span`, `.qf label`, `.qf-foot`, `.hp-tq small`, `.hp-src`, `.hp-report-note`, `.hp-metrics strong`, `.hp-acc dt`, `.hp-gp small`, `.wf-stats span`, and every `.8125rem` or `.875rem` in `site.css`, `plans-page.css`, `repair-page.css`, `footer.css`).
- Tap targets at least 44px high (52px for buttons). Buttons full width inside cards on phones.
- Remove `white-space:nowrap` where it can clip at 320px (`.hp-report-rows b`, `.hp-ring b`, `.wf-stats span`, plan toggle labels). Use `min-width:0` on grid and flex children, `grid-template-columns:minmax(0,1fr)`.
- Interactions are CSS-first (`<details>`, radio + `:has()`, `:target`). Add JavaScript only where CSS cannot do it (the header drill-in panel may extend the existing menu script). Everything must work with the keyboard, have visible focus, and use `aria-expanded` / `role="tablist"` correctly.
- Auto-moving strips: CSS only, `animation: translateX(0 > -50%) linear infinite`, track duplicated once (the copy `aria-hidden`), wrapper `overflow-x:auto` (so people can drag), `tabindex="0"`, `role="region"` with an aria-label, pause on hover, focus and touch (`animation-play-state:paused`), no animation under `prefers-reduced-motion` (then it becomes a normal wrapped grid).
